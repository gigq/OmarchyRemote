# Android parity work

Goal: run the same Omarchy Remote experience on Android phones and larger screens,
verified end to end on the available Android emulator before physical OnePlus 9 testing.
The shared Rust backend and JavaScript providers remain authoritative; Android hosts
the shell and implements native device services and independent browser surfaces.

Completion requires evidence for all of these areas, not just an APK that launches:

The dated sequence below records individual checks and fixes; later entries supersede
older statements that a now-tested flow was still pending. The table above tracks the
remaining acceptance work. Physical-device-only checks are deferred to the OnePlus 9.

No physical-device parity claim is made by emulator validation. Keep remaining gaps
visible here until they are actually implemented and tested.

Initial emulator evidence: `artifacts/android/initial.png`, `terminal.png`, and CDP inspection confirmed platform `android`, live host content, battery state, and typed terminal echo. The initial full-screen OS education dialog was dismissed. The QA-created terminal was closed without sending any input to existing Herdr threads.

Android Gradle `assembleDebug` and `lintDebug` pass. The minimum supported Android version is 11 (API 30); the runtime read of bundled assets avoids newer Java APIs unavailable there.

Weather location: implemented foreground permission handling, denial, disabled services, a 20-second lookup timeout, and cancellation on host change or destruction. Emulator checks verified no unsolicited permission prompt, denial, successful GPS lookup at an injected coordinate, and disabled-service errors. Clicking the weather compass populated the live widget and saved the location; screenshot: `artifacts/android/location-weather.png`. Approximate-only physical-device behavior remains to verify.

Files: the trusted shell now saves through Android’s document picker using chunked staging and background copying. In the emulator, a 480,000-byte fixture saved to Downloads matched byte for byte; cancellation returned AbortError without creating a file. The same file was selected through the real Files app upload button and verified on the host in an isolated temporary folder, then opened and saved through Files’ Save… button. External web pages do not receive this bridge. Later entries verify Herdr image attachments and multi-file upload/ZIP saving. The later native sharing entry covers handoff to a separate app. Folder upload and general external-page downloads are not exposed by the current iPhone wrapper and are not additional Android parity requirements.

Browser control checks: `node scripts/android-browser-smoke.mjs` uses an isolated local website and an independent native view, without modifying desktop tabs. It verifies bridge isolation, user-initiated pushState URL/back-state reporting, back/forward, toolbar reveal only at scroll zero, enabling/disabling DarkReader, native Find match counts and next/close, and actual adb keyboard input after focus moves in both directions. Browser-to-desktop integration and additional lifecycle scenarios still need verification; later entries cover hardware shortcuts and page zoom.

Hardware shortcuts: Android now consumes only registered chords, suppresses repeated command dispatch, and routes canonical actions from both shell and website WebViews. Plain Command actions accept Ctrl+Alt on Android, including browser actions, with shared collision detection. The native browser fixture verifies real adb key combinations and preserved Ctrl+A/C/V editing. A real Ctrl+Alt+Enter launched a host Terminal, typed text reached its PTY after focus became ready, and Ctrl+Alt+W closed it without executing the typed text. Immediate typing during launch, tablet sizing, and the full shortcut matrix still need coverage.

Offline recovery: bundled assets now render at the selected host origin, keeping API/WebSocket routing and local storage aligned. Native foreground retries use a bounded 3–30 second backoff and preserve normal TLS validation. Emulator checks removed only its adb network forwarding (the host services stayed running), force-stopped and launched the app offline, and confirmed Home rendered with existing settings/catalog. An offline storage edit and isolated Herdr draft survived backgrounding and process death, then survived restoration of the live shell on resume. No existing agent received QA input. Killing immediately after a synthetic storage write, before the asynchronous mirror completed, did lose that write; this test does not claim synchronous durability at every instruction boundary.

Foreground recovery also passed without backgrounding or tapping: restoring the emulator forwarding replaced the bundled shell automatically. The persistence regression suite exposed a shared backup omission; widget catalog history is now backed up so hidden Herdr widgets stay hidden after restore.

Immediate Terminal typing: reproduced lost characters before the input field took focus, then added bounded native buffering during registered native-app launch shortcuts. `node scripts/android-terminal-smoke.mjs` exercises immediate launch/type and already-active launch/type in three rounds, verifies the real PTY echo, and closes each owned shell without submitting the text. This does not yet cover every workspace-switch timing or software IME scenario.

Android Back: the native browser smoke test now uses an actual Android Back event for history navigation. Emulator checks also dismissed the launcher and verified root Back moved the task behind the Android launcher; reopening resumed it. The shared shortcut spec verifies overlay and keyboard dismissal state. Files retains its shared on-screen parent-folder controls, as on iOS; Android hardware Back is a shell/browser action rather than an additional Files navigation binding.

Tablet: temporarily resized the emulator to 1280×800 at density 160, inspected Home and tiled-window screenshots, and restored its original 1080×2400/density 420 configuration afterward. `node scripts/android-tablet-smoke.mjs` verifies actual native shortcuts creating and tiling Terminal/Files, an adb touch drag changing the split ratio, three immediate focus/type cycles, and immediate typing after a workspace switch. All created windows/shells are closed without submitting text. This exposed and fixed early character loss on window/workspace transitions by extending the validated native handoff buffer. Screenshots: `artifacts/android/tablet-home.png`, `tablet-tiles.png`, `tablet-resized.png`. Software-keyboard sizing and native browser tile geometry remain to verify.

Further stress testing found Android’s input-method handoff could reorder keys or leak the launch shortcut’s Enter before the activity received them. Registered shortcuts and buffered printable transition keys now run before that input-method stage; replay is serialized and follows the latest validated focus token. Nine rapid phone launch/relaunch cycles and the repeated tablet test passed afterward. Website-owned keyboard focus remains on the website path; the later browser transition checks cover immediate Terminal launch from a focused native page.

Android page zoom now scales the document, including images and layout, from 25% to 500%, preserves authored root zoom on reset, and reapplies after navigation/reload. It uses CSS root zoom because WebView text zoom excludes images and pinch zoom has page-defined limits. CSS zoom does not change viewport media-query breakpoints like desktop browser zoom; sites that replace or continually restyle their document root remain a compatibility edge case. The native browser smoke test checks rendered blue-box and red-image pixel widths, authored-zoom reset, and reload persistence. Pixel checks are required because the emulator’s Chromium 124 reports pre-zoom bounding rectangles for root zoom.

Embedded window focus: Android now honors the focused flag in Browser/web-app layout updates. With a hardware keyboard, activating a visible page requests native focus once and preserves the page’s caret instead of selecting its first input; subsequent animation frames do not repeatedly steal it. Deactivating or hiding a page releases focus only if that page still owns it, protecting sibling update ordering. The native browser smoke test types across shell/page layout transitions and hide/restore without a separate focus command or tap, and checks that sliding partially offscreen preserves the page viewport. The later transition checks cover immediate website-to-Terminal shortcut typing.

Build delivery: the publisher accepts APKs, verifies their signatures with Android build-tools, records platform/package/version/minimum API/certificates, and retains them alongside legacy IPA entries. Download serving includes Android MIME/disposition and HEAD metadata. Native Builds filters by platform. Android downloads only the selected host’s content-addressed APK, checks checksum/package/signing identity/API/version, and hands it to the system installer through a private FileProvider. The emulator exercised denied permission/retry, malformed identity and checksum rejection, cancellation, and an actual version 1→2 update. Installed APK bytes matched the published candidate, saved hosts survived, and the temporary QA host was removed afterward. `scripts/android-update-smoke.mjs` repeats the update flow against an isolated temporary host and can also reinstall the current version. The development app retains debug signing. A later entry verifies configurable release signing; wrong-key/package rejection coverage and remote HTTPS installation remain to verify.

Herdr input: emulator testing uses two new, unfocused host workspaces and never writes to existing agents. It exercises ADB keyboard typing with the software IME visible, per-pane draft switching, process death/relaunch, native image selection, byte-for-byte upload verification, and sending an `echo` command only to the owned shell. This exposed full-screen phone insets being ignored, message Ctrl editing being forwarded to the host, and software IME reopening after Send during hardware-focus reconciliation. Those paths are now corrected. Draft switches also finish the old editor session. Screenshot: `artifacts/android/herdr-input.png`. Touch-key autocorrection/composition (including non-Latin IMEs), multi-file selection, and broader clipboard/selection scenarios still require dedicated native coverage.

Native browser transitions: the installed emulator passes three immediate Terminal launch/type cycles from a focused, isolated website. Each uses a newly owned host PTY, checks that no characters enter the website, and closes without submitting the typed text. The same native browser script verifies a target-blank link navigates inline without launching another Android app, retains a fixture session cookie, remains isolated from the privileged bridge, and returns through Back. These checks exercise the native page adapter; the later isolated desktop integration covers live tab synchronization; the complete saved-app catalog flow remains separate coverage.

Multi-file picker: the emulator exposed dropped uploads when Android returned selected documents in ClipData with no single data URI. The wrapper now handles that collection explicitly and preserves the single-file/cancellation path. `scripts/android-files-smoke.mjs` selects two real device files, verifies both host uploads byte for byte, cancels a second upload, and saves their ZIP back to Downloads, checking its host-relative paths and contents. All files live in owned temporary locations and are removed after the run. The reference iPhone Files UI supports file selection, not directory upload.

Native file sharing: Save… now offers document saving or the system share sheet. The optional `qa-share-receiver` Android module has no network/storage permissions and is excluded from ordinary builds. `scripts/android-share-smoke.mjs` installs it only for emulator testing, selects it in the real chooser, compares a multi-chunk fixture byte for byte, checks filename/MIME/content-URI metadata and denied write access, cancels a subsequent transfer, and uninstalls the receiver. The native implementation preserves cached copies for asynchronous recipients and prunes old copies on startup. Sharing reports chooser handoff rather than external delivery.

Full desktop Browser integration: `ANDROID_BROWSER_QA=1 npm run test:browser-adapter` connects the installed emulator to an isolated backend and Vivaldi profile through a temporary browser-only gateway. Other host APIs are blocked. It opens an actual desktop tab in the Android native view, verifies bridge isolation, follows a page link and observes the exact desktop tab URL change, and closes the tab through the native shortcut while retaining the app window. It rejects unsafe host addresses, disconnects through the shared host UI, restarts into the host picker, reconnects from its saved row, checks retained host-local data, and restores the original host without leaking the fixture preference. The original desktop profile and other host apps are never used. The following TLS check covers certificate rejection and the native Add host dialog.

Untrusted HTTPS: `scripts/android-tls-smoke.mjs` creates a short-lived self-signed server, adds it through the actual Android Add host dialog and opens its saved row. The emulator rejects its certificate: the fixture receives TLS attempts but zero HTTP page/API requests, including automatic reconnect probes. Bundled Home loads under the selected host scope, Disconnect reaches the host picker, and reconnecting preserves an offline fixture preference. The test restores the original host without leaking that preference and deletes the temporary certificate. No CA is installed and no trust setting is changed.

Gboard touch entry: `ANDROID_TOUCH_IME_QA=1 node scripts/android-herdr-smoke.mjs` uses actual screen taps on the English portrait keyboard of the 1080×2400, density-420 emulator. It checks the exact draft and trusted input events before tapping Gboard’s Send key, verifies output only in its newly created shell, and checks draft clearing and IME dismissal. The fixture rejects a different screen size, density or input method and removes its own workspaces. This Gboard configuration emits direct text input; it does not establish predictive correction or composing-script coverage.

Saved-app lifecycle: `scripts/android-webapps-smoke.mjs` runs the real management UI and native page adapter against an isolated in-memory catalog (not the production backend catalog). It installs and opens an app without browser chrome, follows a target-blank link inline, checks privileged-bridge absence and Android Back, then kills/relaunches with catalog requests disabled. The local catalog, pin and persistent session cookie survive. Uninstall removes the catalog entry, pin and open window. The fixture restores the original host and removes its temporary host. Screenshot inspection exposed a dark default website canvas with unreadable black text; native page WebViews now use white by default while the shell stays themed. A screenshot pixel assertion covers the default canvas. Authored backgrounds and the existing DarkReader toggle remain site-controlled.

Tablet native-page geometry: `ANDROID_TABLET_WEBAPPS_QA=1 node scripts/android-webapps-smoke.mjs` passed at 1280×800/density 160. Two separately installed fixture apps are moved into one workspace using the real shortcut. Each native page's viewport matches its shell tile, including after an ADB divider drag. Loaded snapshots appear in Expo while the full-size page surfaces disappear; a native screenshot pixel check and visual inspection confirm the overlay is not covered by those surfaces. Leaving Expo restores both dimensions. The test then removes the second app and completes the saved-app process-death, offline-catalog, cookie and uninstall checks. Android WebView visibility does not update `document.hidden` here, so that property is not used as evidence of native surface visibility. Screenshots: `artifacts/android/tablet-webapps.png` and `tablet-webapps-expo.png`. The emulator was restored to 1080×2400/density 420 afterward. This closes the tablet browser geometry gap; tablet software-IME layout remains a separate check.

Tablet software IME: the existing native Herdr fixture passed at 1280×800/density 160. The settled inset was 320 CSS pixels; the composer ended at y=463, above the keyboard at y=480, with 349 pixels of output remaining. The fixture now waits for five identical geometry samples and verifies output height/placement as well as composer visibility, avoiding screenshots taken mid-animation. It records measured JSON and a native screenshot (`artifacts/android/tablet-herdr-input.*`). The screenshot confirms the complete draft and Send control are visible above split Gboard. Draft switching, clipboard copy/paste/undo, native image attachment, process-death restoration and real Send/dismiss run against newly owned Herdr shells. The emulator is returned to its original phone dimensions afterward.

The tablet run also corrected the test's Downloads selection: the title bar and navigation drawer share that text, so the fixture now selects the drawer item's resource ID. Previously it left the drawer open and accidentally launched Drive, which returned a canceled picker result; the app correctly received no file. One exploratory tablet run also timed out after clipboard Undo; subsequent runs passed that step, and failure diagnostics now retain the exact draft and selected-file metadata. Repeated clipboard/IME stress remains an open verification item.

Release signing workflow: `docs/android-signing.md` documents an explicit private keystore and four environment variables. Gradle signs release APKs with that configuration and fails missing/partial configuration rather than using the debug key. `scripts/android-release-smoke.py` creates a temporary key and separate emulator identity, builds release versions 401/402, verifies a stable certificate and non-debuggable/HTTPS-only manifests, installs and launches both, and verifies that an in-place update retains a host added through the native dialog. `run-as` is denied. The fixture never connects to its example host, removes its QA installation/key, and returns to the normal app. Screenshot: `artifacts/android/release-host-picker.png`. This verifies release packaging and update mechanics; a durable distribution key and real private-HTTPS release-host connection are not claimed by the disposable test identity.

Shared regression baseline: the full Playwright suite passed 152/152 tests, the isolated backend suite passed 14/14, native bundle packaging passed 2/2, and build publication packaging passed 2/2. Logs are retained under `artifacts/validation-android-parity/`. These cover shared app behavior; native emulator checks above establish Android integration and are not replaced by desktop-browser results.

Native phone shell: real topbar/edge/bottom swipes exercised the launcher, workspace navigation and Expo. Real long presses reordered Expo cards and Home pins; card swipes closed owned windows. Catppuccin, the bundled Totoro wallpaper, pins and widget order survived force-stop/relaunch. The swipe-open launcher check exposed missing native WebView focus: the first keystroke selected Home’s first button. The shell now acquires native focus on touch-down and disables initial-element selection. Cold-launch swipe/immediate typing and the native launcher shortcut passed after rebuilding.

Host-switch snapshot regression: `node scripts/android-host-state-smoke.mjs` uses two isolated temporary hosts and blocks host APIs. A unique value exists only in the native host-switch payload, so a delayed preference mirror cannot make the test pass. The native snapshot survives A→B→A switching and process death; wrong-scope storage and host requests cannot overwrite another host. Both fixtures are removed and the original host restored. Log: `artifacts/validation-android-parity/host-state.log`. Final shared gates passed again: `npm test` 12/12 and `npm run lint`, after `npm run format`.

Launcher Escape follow-up: the first Escape was intercepted before DOM delivery. Android now routes unmodified Escape to the active WebView before the input method; Android Back retains keyboard dismissal. The repeatable `scripts/android-launcher-smoke.mjs` waits for dashboard handlers and a settled viewport, then verifies real swipe/immediate input, native focus, exactly one first-Escape keydown and dismissal, Ctrl+Alt+K input, and Home-only restoration. It passes on the rebuilt emulator app. An earlier cold-start attempt lacked that readiness check, and another correctly stopped on a non-Home layout; neither is counted as a passing regression run.

Browser Dark persistence: Android stores the forced Dark preference, reports it through capabilities and applies it to newly created native pages. The isolated browser smoke verifies actual DarkReader styling and computed background/text colors after enable, close/reopen, process death/relaunch, disable and another restart. The original device preference is restored. Log: `artifacts/validation-android-parity/android-browser-dark.log`; Gradle build/lint, npm test (12/12), formatting and lint passed.

Native page pointer focus: Android forwards mouse hover to the shared opt-in focus policy and returns the event to the website. The tablet saved-app fixture injects button-free `ACTION_HOVER_MOVE` through Android InputManager and verifies setting-off stability, setting-on focus transfer, real website pointer events and CSS hover. The same run passes tile sizing, divider resize, Expo and saved-app lifecycle checks. The QA helper is not part of the installed app. It intentionally emits only MOVE; Android generates hover enter/exit transitions. Defensive button/tool filters were reviewed but are not claimed as independently injected native coverage. The original phone dimensions and connected Home-only host were restored.

Device services: `scripts/android-device-services-smoke.mjs` exercises three simulated battery states and verifies both the native broadcast data and visible battery labels.
